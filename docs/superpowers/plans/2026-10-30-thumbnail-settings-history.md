# Thumbnail settings and per-file viewing history

- Settings: two native rows alongside thumbnail size/limit; ConfigSettingsStore bridges existing per-app UserDefaults with validation/reset/notifications, avoiding a second source of codec defaults. Relaunch applies encoding changes consistently to writer and namespace; describe this inline. Existing SQL cleanup controls stay as they are.
- History: StateDatabase additive file_views table, keyed by local standardized file URL or source URL, distinct from Catalog.db/Thumbs.db. Addressed reads on workers, one shared history writer, bounded coalescing and no startup scan. Preserve on thumbnail clear, follow local renames, monotonic timestamps across windows.
- Presentation: one-shot immutable receipt per photo visit; Metal drawable presentedTime > 0 records it only after an actually presented non-held visible image. Color/zoom/refinement frames reuse the receipt; returning to a different photo creates a new receipt. Companions get independent receipts and must intersect viewport.
- UI: common FileFacts.lastViewedAt optional field feeds existing Last Viewed table column and inspector; source queries history off main and merges it into delivered facts, never substitutes cache-access timestamps.
- Verification: preferences/validation/reset/row metadata; history reopen/cache-clear/rename/absence/monotonic writes; one-shot receipt and failed presentation; actual visible integration, targeted and full tests; native Settings first/repeat CPU bench. Independent review before build/install, Intel limitation explicit.
