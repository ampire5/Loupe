# Тулбар Home на `NSToolbar` (этап 1 из 3) — дизайн

Дата: 2026-10-24. Запрос владельца: давно откладываемая отрисовка верхнего тулбара — системный `NSToolbar` вместо
самописного `HomeToolbar`, по образцу Photos на macOS 26. Объём этапа: только тулбар браузера Home; тулбар просмотра —
этап 2, сайдбар на системных компонентах — этап 3. Раскладка согласована 2026-10-22, решения по полному экрану —
2026-10-23; спайк (две схемы, замеры, запись мигания) — 2026-10-24.

## Цель

- Читаемый путь и подписи: заголовок и подзаголовок окна вместо панели с крошками поверх содержимого (её плохо видно
  на пёстрых превью).
- Место под пилюлю прогресса эскизов на обычном окне: сейчас она прячется ниже ~1120 pt, потому что тулбар переполнен.
- Системное стекло, прозрачный тулбар с содержимым под ним, перетаскивание окна за тулбар, `»` при нехватке места,
  полный экран с выезжающим тулбаром, системная полоса вкладок — без собственного кода под каждое.
- Меньше своего кода: уходят `HomeToolbar` (483 строки), его градиентная подложка, ручная раскладка и расчёт
  «сколько осталось места пути»; ступени пилюли заменяет приоритет скрытия.

## Решения

- **Схема: два готовых `NSToolbar`** (браузер и, на этапе 2, просмотр), смена `window.toolbar = …`. Один тулбар с
  заменой items отвергнут: в 5 раз дороже и мигает. На этапе 1 при переходе в просмотр `window.toolbar = nil`, пока
  просмотр сидит на своей панели (стоимость этого шага — в замерах плана).
- **Как Photos.** `NSWindow.toolbarStyle = .unified`, `styleMask` с `.fullSizeContentView`, прокрутка сетки идёт под тулбар;
  прозрачность и мягкое затемнение края даёт система (подтверждено спайком). Своя подложка и свои стеклянные
  группы (`GlassGroup`, `GlassCapsule` в этом месте) не используются.
- **Текст — в заголовке окна.** `window.title` — имя папки или раздела; `window.subtitle` — «412 photos · 18 folders ·
  1.9 GB · 1.2 TB free» (счёт, объём и свободное место из backlog; пока листинг не пришёл — «…»; «Loading…» как сейчас;
  сегодняшняя строка подзаголовка панели не меняется, к ней добавляются объём и место). `window.title` видят Mission
  Control и меню «Окно»; метка вкладки остаётся нынешней («Recent», «Folders», …) и задаётся отдельно через
  `window.tab.title`. В полном экране тулбар выезжает со строкой меню и несёт тот же текст; своих правил показа нет.
- **Крошки — пилюля-меню** (`NSMenuToolbarItem`, значок папки ▾), как первая пилюля у Photos: в меню предки текущей
  папки от неё вверх, текущая с галочкой, «Places» последним. Клик по пункту — `onCrumb`. Соседние папки — подменю у
  пункта (как нынешний `siblingMenu`), заполняется лениво. Заголовок остаётся текстом, меню у него нет.
- **Фильтр — текстовые сегменты** `Всё | Папки | Фото` (`NSToolbarItemGroup`, `.selectOne`); страничный фильтр
  (`pageFilters`) — второй item той же ширины, прячется через `isHidden`, пока не нужен: пересборка группы дороже.

## Раскладка

Слева направо (подписи — как в приложении, по-английски):

`◧ Sidebar` │ `⌂ Start Page` │ `‹ ›` │ `[папка ▾]` │ ⟵ гибкое место ⟶ │ `All | Folders | Photos` │ ⟵ гибкое место ⟶ │ `◔`
(кольцо прогресса) │ `Posters | Cards | List` │ `− +` │ `View ▾` │ поиск.

Пилюли — по смыслу: «где я» слева (сайдбар, домой, история, путь), «что показываю» по центру, «как показываю» справа.
Поиск — `NSSearchToolbarItem`: сворачивается в лупу сам (замерено: при ≲ 900 pt).

Перенос нынешних элементов:

| Сейчас | Станет |
|---|---|
| Sidebar, Start Page, ‹ ›, `↑ Enclosing Folder` | Sidebar, Start Page, ‹ ›; «↑» убрана (решение 22.10: дублирует путь и ⌘↑) |
| Путь из крошек + подпись под ним | `window.title` / `window.subtitle` + пилюля пути |
| Kind capsule, page filter | сегменты `All | Folders | Photos`; страничный фильтр — второй item |
| `−` `+` | группа `− +` (momentary) |
| Card switch (Posters / Cards / List) | остаётся на тулбаре группой `.selectOne` из трёх значков, пока есть место (решение владельца 2026-10-24); при нехватке места уходит за `»` по приоритету; вне папки скрыт (`isHidden`), как сейчас; те же три пункта дублируются в `View ▾` с галочкой |
| Sort capsule (Name / Date / Size), аспект «Square or Aspect» | в `View ▾`: Sort by… (поля источника, активное со стрелкой направления), Square / Aspect; сочетания клавиш остаются в меню; «Folders First» не добавляется: в браузере такой настройки нет, она только у сайдбара |
| Поле поиска и его фокус (⌘F) | `NSSearchToolbarItem`; `focusFilter()` ставит фокус в него |
| `ThumbsProgressPill` в трёх ступенях (full / compact / hidden) + popover | кольцо в тулбаре (custom view), текст — в подсказке; popover — по клику, как сейчас; ступеней нет |
| `LoadingLine` по нижней кромке тулбара | остаётся своей линией под тулбаром (привязка к `contentLayoutGuide`): тулбар её не вмещает |

Прогресс-кольцо — свой слой (штатный `NSProgressIndicator` в пилюле выглядит неаккуратно), размер задан констрейнтами
(30 × 28 pt). Когда прогресса нет, item скрыт (`isHidden`); когда есть, ничего не анимируется, кроме самого кольца, и
оно останавливается вместе с работой («тишина в покое»). Обновление значения 100 раз: медиана 0,01 мс.

## Узкое окно

Скрытие — по `visibilityPriority`, система прячет и показывает `»` сама; произвольные целые приоритеты работают
(замерено). Порядок скрытия (первым уходит меньший):

| Приоритет | Item |
|---|---|
| −300 | `View ▾` |
| −250 | переключатель `Posters / Cards / List` |
| −200 | `− +` |
| −100 | сегменты фильтра |
| 0 | ‹ › |
| 10 | Start Page |
| 50 | пилюля пути |
| 80 | кольцо прогресса |
| 100 | поиск (сам сворачивается в лупу раньше) |
| 1000 | Sidebar |

Замер зонда с переключателем карточек (ширина окна, pt; шаг 20; всё видно при ≥ 1120): `View ▾` и переключатель
карточек уходят вместе при ≤ 1100, `− +` ≤ 980, фильтр ≤ 900, ‹ › ≤ 640, Start Page ≤ 560, путь ≤ 480, кольцо —
последним, ≤ 420. Скрытое остаётся доступно через `»`. Раньше пилюля пропадала ниже ~1110–1120 pt; теперь на окне
~900 pt она видна вместе с путём, историей и поиском, а при полной ширине (≥ 1120) видно всё. Таблицу перемерить на
реальном окне в плане. Минимальный размер окна задаёт приложение;
вопрос «что обязано быть видно» решён: сайдбар, кольцо, поиск, заголовок.

## Быстродействие (бюджеты из `CLAUDE.md`, Intel i7-10700K, macOS 26.7.1, release)

| Что | Замер зонда (главный поток, CPU) | Бюджет |
|---|---|---|
| Открытие окна с тулбаром браузера | 244–275 мс | 300 мс |
| Смена набора, повторная | вызов 9–13, полное 19–28 мс, круги не растут | 100 мс |
| Первая смена на тулбар просмотра (холодная) | 105–127 мс (этап 2) | 100 мс |
| Холодная смена с прогревом при открытии окна | 27 мс, но открытие окна 382–400 мс | — |
| Обновление кольца | 0,01 мс (медиана) | 50 мс |
| Мигание при смене | нет: 310 кадров записи, все совпали с чистым состоянием | — |

- **Бенч до сдачи** (по правилу «новый экран — бенч»): реальное окно Home, число CPU главного потока на действие
  (`CLOCK_THREAD_CPUTIME_ID`): открытие окна, переход Home ↔ просмотр, 12+ кругов, первый заход отдельно, сужение окна
  шагами по 20 pt, 100 обновлений кольца, открытие `View ▾` и меню пути. Таблица «до/после» относительно нынешнего
  `HomeToolbar` — в документ бенча.
- **Меню наполняются лениво** (`NSMenuDelegate.menuNeedsUpdate`): `NSPopUpButton` на macOS 26 меряет каждый пункт ~1 мс;
  до первого открытия в меню один пункт.
- **Холодный первый заход** на этапе 1 возникает только в приложениях, где окно открывается с Home (замер бенчем на
  реальном окне, не зондом); решение по холодным 105–127 мс (принять / переключатели без пилюли / прогрев) —
  владельцу на этапе 2, когда появится тулбар просмотра. Прогрев при создании окна на этапе 1 не делаем: он выводит
  открытие за бюджет 300 мс.
- Разделы Home (Recent, Sessions, Stash) — **на одном тулбаре**, меняется только заголовок и состав видимых items; на
  каждый раздел отдельный `NSToolbar` заплатил бы холодным заходом.
- В простое тулбар ничего не делает: таймеров нет, кольцо скрыто без работы.

## Затронутые места

- **HomeScreenKit:** новый `HomeToolbarController` (владеет `NSToolbar`, `NSToolbarDelegate`, `NSMenuDelegate` для
  ленивых меню); тот же набор вызовов `show(path:…)`, `show(title:)`, `show(subtitle:)`, `show(sort:keys:)`,
  `show(pageFilters:selected:)`, `show(filter:visible:)`, `show(style:)`, `show(cardStyle:visible:)`,
  `show(progress:)`, `show(progressDetail:)`, `focusFilter()`, чтобы `HomeBrowserView` менялся минимально: убирается
  `toolbar` как subview и `HomeToolbar.height` в метриках (`metrics.top`, прокрутка к элементу, список) — верхний
  отступ берётся из `contentLayoutGuide` / `safeAreaInsets.top` окна. Колбэки (`onCrumb`, `onBack`, … `onFilterEnd`) те же.
  Тесты `HomeBrowser*Tests`, которые читают `toolbar.crumbTitles`, `kindTitles`, `isProgressVisible` и т. п., переходят
  на запрос к контроллеру; тест `narrowToolbarHidesThePillFirst` заменяется проверкой `visibleItems` на ширинах таблицы
  приоритетов.
- **Loupe:** `ViewerWindowController` — `.fullSizeContentView`, `toolbarStyle = .unified`, присвоение
  `window.toolbar` при показе Home и `nil` при показе просмотра; `window.tab.title` берёт то, что сейчас получает
  `window.title` из `WindowTitle.text` (метки вкладок не меняются), а `window.title` / `subtitle` на Home получает от
  `HomeToolbarController`, в просмотре — по-прежнему из `WindowTitle.text`. Полный экран и вкладки (`tabbingMode = .preferred`) — проверить на реальном
  окне: тулбар окна вкладки, полоса вкладок под ним.
- **Settings / документация:** `Settings › Performance` без изменений; `docs/bench` — документ бенча; `README` — только
  если у Home появится видимое для пользователя описание.

## Не входит в этап

- Тулбар просмотра, переключатели с нейтральной пилюлей (замок, лента, статистика, Info), «Quality» с подсветкой
  отличий от умолчаний, подпись «N / M · NN %» — этап 2 (там же решается обрезание подписи на окне ≲ 700 pt:
  подпись обрезается раньше, чем уходят кнопки, API на приоритет заголовка нет).
- Сайдбар на системных компонентах — этап 3; пока кнопка сайдбара — обычный item тулбара, а не на линии светофора.
- Индикатор положения в полном экране и `ChromeHUD` — свои этапы, с тулбаром не пересекаются.

## Проверка и риски

- Реальное окно, скриншоты: Home в светлой и тёмной теме, окна 1200 / 900 / 700 / 560 pt, полный экран, вкладка, окно
  с длинным путём и длинным именем папки (подзаголовок и путь при обрезании).
- Риск: сегменты с текстом шире значков — при 900 pt уходят «View» и «− +», при ≤ 880 pt — сам фильтр; если это мало,
  вернуть значки (уходят при ≈ 700 pt) — решение после скриншотов на сборке.
- Риск: `visibilityPriority` честно действует, но порядок равных приоритетов — на усмотрение системы: приоритеты в
  таблице все разные (в зонде «‹ ›» и Start Page были равны и уходили в порядке расположения; теперь Start Page 10).
- Риск: `NSToolbarItemGroup` не умеет менять число сегментов без пересборки — поэтому два item'а фильтра.
- Проверить в плане: пилюля пути и меню на длинных путях (> 12 предков, SMB, архивы с `∕` в именах), доступность
  (VoiceOver, подписи item'ов, Reduce Motion не затронут — анимаций нет), русская и английская локали подписей.
